# 逛 Linux.do：我收藏的几篇 AI 好帖

最近经常泡 [Linux.do](https://linux.do)，这是一个氛围很好的开发者社区，AI 相关板块的讨论尤其活跃。相比碎片化的社交媒体，这里的很多帖子有完整的背景、推导和踩坑记录，值得反复回看。

![收藏的帖子配图 w-100](/assets/posts/linuxdo-ai-posts.webp "把好帖收藏起来")

这篇文章整理我最近收藏的几篇 AI 相关帖子，附上原文链接和我自己的读后笔记。

## 一、提示词到底该怎么写：[手把手教你如何编写提示词](https://linux.do/t/topic/860454)

这是我认为最适合入门的一篇。作者没有直接甩模板，而是先讲清楚原理：LLM 本质上是基于条件概率预测下一个 token 的模型，而**提示词正是我们输入给模型的上下文**——理解了这一点，很多"技巧"就不再是玄学。

文章给出的提示词框架包含九个部分：Role（角色）、Profile（人物设定）、Skills（技能清单）、Background（背景）、Goals（目标）、Constrains（限制条件）、Workflow（工作流程）、OutputFormat（输出格式）、Examples（示例）。作者用一个"事实核查助手"做完整演示，并且强调这些部分**不必全部堆上，按需精简**——随着模型能力增强，越来越短的提示词也能获得好结果。

我的收获是：写提示词前先想清楚"我要什么、不要什么、按什么步骤做"，这三件事对应的就是 Goals、Constrains 和 Workflow。

## 二、让 AI 帮你写提示词：[分享下我做提示词的几个方法](https://linux.do/t/topic/731017)

这篇更进阶一层：既然提示词这么重要，能不能让 AI 参与生产提示词？作者总结了四个方法：

1. **DeepSearch**：当自己说不清"什么算好"时（比如翻译质量），先用深度搜索研究清楚好的标准，再把研究报告交给模型生成初版提示词；
2. **模仿**：把某个人的大量内容喂给 AI，分析其思维框架，生成定制版提示词；
3. **对话**：与已有提示词针对具体问题探讨，最后让 AI 提炼出解决框架；
4. **直接生成**：用高阶模型直接生成，再用优化器迭代，前提是你能**精确指出哪里不符合需求**，而不是笼统地说"不好"。

社区里还有一篇[自用的"让 AI 写 prompt 的 prompt"](https://linux.do/t/topic/726795)，把元提示词的做法具体化了。这类方法的核心其实是同一个：把模糊的期待翻译成可验证的标准。

## 三、Claude Code 上手：[使用手册](https://linux.do/t/topic/1871092)与[常用命令笔记](https://linux.do/t/topic/1948703)

如果你刚开始用 Claude Code 这类编程智能体，[《Claude code 使用手册，可以帮助新手快速上手》](https://linux.do/t/topic/1871092)覆盖了从安装到生产落地的完整流程。几个我觉得最实用的点：

- **三种交互模式**（Shift + Tab 切换）：默认模式每次改文件前询问、自动模式不再询问、规划模式（Plan Mode）只讨论方案不写代码。大改动前先切 Plan Mode 讨论清楚，是社区反复强调的习惯；
- 输入 `!` 可以直接执行终端命令，输出会自动进入对话上下文，跑失败的测试再让模型分析非常顺手；
- 按 `Ctrl + G` 可以把当前输入内容丢到 VS Code 里编辑，长提示词不用在终端里受罪。

另一篇[学习笔记](https://linux.do/t/topic/1948703)整理了写给模型的约束，比如"不要顺手重构无关代码""把任务转成可验证的目标：写测试，让测试通过"。这些原则和我自己使用中的体会完全一致：**给智能体划边界、给验收标准，比堆砌需求有效得多**。

## 四、更远的路线图：[致新生的你：关于 AI 入门以及科研相关的建议](https://linux.do/t/topic/1710548)

作者是还在读大三的学生，但这篇帖子可能是中文社区里少见的、既有方法论又有具体路径的 AI 入门长文。核心路线是：先补齐高数、线代、概率论的最小数学基础 → 学会 Linux 和 Python、能独立跑通项目 → 通过 CS231n 等课程进入深度学习并补 PyTorch → 掌握 Codex / Claude Code 等编程智能体加速后续一切环节 → 选定方向读经典论文 → 再申请第一段科研实习。

作者特别强调两点：**先打基础再进组**，因为课题组有自己的方向偏好，零基础进组学到的可能不是主流技术栈；以及**直接瞄准目标领域的强组**，因为 AI 领域各方向之间"触类旁通"是幻觉，冷门领域积累的可能只是落后的技术。

他对 Coding Agent 的判断也很有意思：Agent 把大多数人的编程水平拉平了，个人的代码能力应该始终处于"过剩"状态，科研的并行度因此变得更重要。

## 小结

回看这几篇帖子，它们分别覆盖了 AI 使用的三个层次：**怎么问**（提示词）、**怎么用工具**（Claude Code）、**怎么走得更远**（学习路线）。Linux.do 的可贵之处在于，这些内容都来自真实使用者的第一手经验，评论区还常常有高水平的追问和补充。

如果你也在这类社区冲浪，建议养成"读完留痕"的习惯：把好帖的链接、要点和自己的质疑记下来。信息本身不稀缺，经过自己消化的信息才稀缺。
