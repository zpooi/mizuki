# 代理节点显示断开，为什么应用还在收到响应？

如果代理面板显示断开，但 Claude Desktop 里的回答还在继续，不能只凭界面判断请求改成了直连。既有连接、应用自己的代理设置和状态面板可能处在不同层；没有本机连接日志时，实际出口仍需验证。

## 可能发生了什么

- **旧连接还没结束**：界面显示节点失联，并不必然意味着已建立的 TCP/TLS 流立即断开。
- **进程走的是另一条代理路径**：桌面应用可能使用自己保存的代理配置，和系统托盘中的全局状态不同。
- **状态面板只监控一个环节**：代理客户端、远端节点、目标服务和应用连接可能有不同的健康状态。
- **连接已结束但应用仍显示生成**：客户端可能在缓冲或渲染已收到的数据，界面动画不等于网络仍在传输。

## 用新连接做一次可验证的检查

1. 记录当前应用的代理设置，以及代理客户端的连接日志。
2. 关闭当前生成会话，再开一个新的短请求；旧会话不能代表新连接的路由。
3. 检查新请求是否出现在本机代理日志中，并确认目标域名、时间和进程一致。
4. 如果仍有疑问，用不包含账号凭证的测试请求检查网络出口；同时确认应用没有备用系统代理或浏览器代理设置。

担心隐私时，应当把“应用连接可能绕过预期代理”当作待验证的网络配置问题，先退出应用、核对路由与连接记录。不要根据一条社区回复就断定服务直连、封号风险或节点状态。
