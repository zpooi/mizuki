# 编程 Agent 靠"复制"读终端？装上 shell 让它直接读进程

> 案例整理自 linux.do 原帖：[关于augment读取终端靠复制的解决办法](https://linux.do/t/topic/753277)

![Agent 读取终端配图 w-100](/assets/posts/linuxdo-agent-terminal.webp "让 Agent 直接读进程")

## 问题现象

使用 Augment 这类编程 Agent 时，会发现它读取终端输出的方式很原始：**大约每 0.5 秒复制一次终端内容**来判断命令是否执行完毕。

表现是终端里频繁出现选中/复制的闪烁，响应也慢。更常见的正常行为应该是"写命令 → read process"，直接读进程输出。

## 原因分析

Agent 之所以退化成"复制"，大多数情况是**它在系统里找不到可用的 shell 可执行文件**：

- 环境里没有安装 `bash`、`fish`、`zsh`（尤其是精简的容器镜像、全新服务器）；
- 或者安装了，但不在 Agent 预期查找的路径里。

找不到 shell，就只能退回最保守的方案——读取终端画面。

## 解决方案

### 方案一：安装 shell（推荐，治本）

```bash
sudo apt update
sudo apt install -y bash      # 或 fish / zsh
```

安装完成之后，**再**到 Augment 的设置里指定使用 bash 或 fish。注意顺序：必须先安装，设置里才能选中，否则选项会无效。

安装后 Agent 就能找到 shell 并改用进程读取，复制闪烁的问题随之消失。

### 方案二：切换为等待模式

如果暂时不想改环境，可以在对话里直接告诉 Agent：

> 使用等待模式启动（不要用复制读取终端）。

这是行为层面的约束，效果不如方案一稳定，但作为临时手段可用。

## 延伸：这类问题的通用判断

凡是出现"Agent 用奇怪的方式兜底完成任务"，基本都可以按这个思路查：

1. 它依赖的底层工具是否存在（`which bash`、`which git`、`which node`）；
2. 工具是否在 PATH 里；
3. Agent 的配置里是否指定了正确的可执行文件路径。

很多"AI 不好用"的体验问题，根源其实是**环境缺件**，而不是模型能力不足。

## 小结

这个案例很小，但很有代表性：Agent 的能力边界常常由环境决定。遇到它行为异常时，先检查它依赖的命令是否安装、能否被找到，往往比反复调提示词有效得多。

顺手确认一下服务器上的 shell，可能就省掉了后面一堆莫名其妙的兜底行为。
