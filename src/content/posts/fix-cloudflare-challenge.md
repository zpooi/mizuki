# 页面上的"小蓝点"一直不消失？聊聊 Cloudflare 盾与 429 的排查

> 案例整理自 linux.do 原帖：[佬友们，请问下为什么小蓝点不消失](https://linux.do/t/topic/1968856)

![过盾排查配图 w-100](/assets/posts/linuxdo-challenge.webp "先搞清楚卡在哪一层")

## 问题现象

打开站点后，界面上有一个"小蓝点"一直在转、不消失，页面内容迟迟加载不出来；有时候直接报 **403**，或者 F12 里能看到某个接口报错。

社区里这类求助非常高频，而答案往往不是单一的。原帖的回复把所有可能性都覆盖了，正好可以整理成一条排查链。

## 四类原因与对应解法

### 一、没有通过 Cloudflare 人机验证（过盾）

最常见的成因。解决方式是手动访问一次验证入口：

```
https://linux.do/challenge
```

访问后强制刷新浏览器（Windows：`Ctrl + F5`；macOS：`Cmd + Shift + R`）。有佬友补充：过盾后页面显示"找不到页面"是正常的，进入即代表已完成验证。

验证不通过时，F12 里通常能看到某个请求报错，这是重要的判断依据。

### 二、代理节点问题

原帖提问者最终确认"是节点造成的"。切换节点再强制刷新，往往立刻恢复。

延伸一点：如果用全局模式容易出现 403，换成规则模式通常更稳定——不同模式决定了请求是从哪里出去的，IP 的"干净程度"直接影响验证结果。

### 三、浏览器安全 DNS 与代理冲突

这是另一个帖子里最容易踩的坑：**浏览器开启了"安全 DNS"（Secure DNS）后，域名解析在浏览器内部就完成了**，代理工具收到的只是 IP，只能按 IP 分流，结果就是分流规则失效、站点打不开。

解决办法二选一：

1. 关闭浏览器的安全 DNS，让代理接管解析；
2. 或者在代理里配置指定域名走指定 DNS，例如 Clash Verge 的全局扩展覆写配置：

```yaml
dns:
  enable: true
  nameserver-policy:
    "linux.do": "https://<你的DOH地址>/query-dns"
    "*.linux.do": "https://<你的DOH地址>/query-dns"
```

注意：某些情况下每次开机需要重新保存一次覆写配置，这是已知的小毛病。

### 四、服务器负载过高（429）

如果服务端压力过大，会返回 429（Too Many Requests），表现为请求被拒绝、状态一直转圈。这种情况用户侧无解，只能稍后重试。

## 通用排查顺序

把上面四类按"从本地到远端"排序，就是一条可复用的排查链：

1. 先看 F12 里是哪个请求失败、返回什么状态码；
2. 403 / 验证失败 → 手动过盾 + 强制刷新；
3. 仍然不行 → 换节点、切换全局/规则模式；
4. 确认浏览器安全 DNS 是否关闭；
5. 状态码是 429 → 服务端限流，等待即可。

## 小结

这类"看起来是网站坏了"的问题，实际原因可能落在**浏览器、代理、网络链路、服务端**任意一层。

最好的习惯是先看状态码和失败的请求，再逐层排除——而不是一上来就清缓存、换浏览器、重启机器。状态码会告诉你该往哪一层查。
